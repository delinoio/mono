# protos-sandcrew API contract

## Scope

This contract owns the protocol schemas of [`sandcrew`](project-sandcrew.md) at `protos/delino/sandcrew/v1/`: the Connect RPC API of `sandcrew-api` and the bridge schema that the [bridge](cmds-sandcrew-bridge-foundation.md) and the [control plane](servers-sandcrew-api-foundation.md) exchange. The directory `protos/delino/sandcrew/` is also the TypeScript binding workspace package `@delino/sandcrew-protos` (not published), according to `protos/AGENTS.md`.

Files: `v1/common.proto` holds the enums that the Connect API and the bridge schema share, `v1/bridge.proto` holds the bridge schema and its enums. The Connect API services and their messages are added with the control plane implementation; until then the directory has no `sandcrewv1connect/` bindings.

## Runtime and Language

- Protocol Buffers (proto3) with Connect RPC, generated with buf like the [SandRun schemas](protos-sandrun-api-contract.md#runtime-and-language): committed Go bindings (`*.pb.go`, `sandcrewv1connect/*.connect.go`) and committed TypeScript bindings (`v1/*_pb.ts`), generated by `scripts/protos.sh generate`.
- The bridge schema is encoded as protobuf JSON (the canonical proto3 JSON mapping), one message per line, because it crosses the dev session exec output and guest files, which carry bytes and not protobuf frames.

## Users and Operators

- `sandcrew-api` (server of the Connect API, reader of bridge events, writer of bridge input).
- `sandcrew-console` (client of the Connect API).
- `sandcrew-bridge` (writer of bridge events, reader of bridge input).

## Interfaces and Contracts

### General rules

- Package: `delino.sandcrew.v1`. A breaking change of the Connect API needs a new package version (`v2`). Within `v1`, do not reuse or renumber fields, do not change field types, and reserve the numbers and names of removed fields.
- Identifiers are UUID v7 values in canonical text form in `string` fields named `<entity>_id`. `organization_id` is the SandRun organization ID. `dev_session_id` is the SandRun dev session ID. User ID fields (`user_id`, `owner_user_id`) hold the Logto `sub` unchanged.
- Times use `google.protobuf.Timestamp`. Durations use `google.protobuf.Duration`. Sizes use `int64` fields with a unit suffix.
- Every enum has a zero value `<ENUM>_UNSPECIFIED`. The server rejects `UNSPECIFIED` in a required enum field with `invalid_argument`. Enum value names follow the buf `STANDARD` lint rule (for example `SESSION_STATE_PAUSED`); the tables below list the values without the prefix.
- List RPCs use `page_size` (default 50, maximum 200) and an opaque `page_token`. An undefined enum number in a list filter fails with `invalid_argument` that names the field.
- Every public RPC is unary or server-streaming. A server-streaming RPC returns a `<Rpc>Response` message that wraps its event.
- Errors use Connect error codes. Detail messages never contain credentials, secrets, prompts or agent output.
- Credential and secret values exist only in request messages of set operations. Response messages carry `value_set_at` and never the value.
- Every RPC except `OrganizationService.ListOrganizations` and the `NotificationService` RPCs takes an `organization_id`.

### Organization settings messages

- `OrganizationSettings`: `organization_id`, `allowed_runner_profile_ids` (SandRun `DEV_SESSION` runner profile IDs), `pause_delay` (`Duration`), `paused_session_retention` (a `oneof` of `duration` and `unlimited`), `update_time`.
- `UpdateOrganizationSettings` takes the settings and a field mask with the paths `allowed_runner_profile_ids`, `pause_delay` and `paused_session_retention`. A masked path without a value restores the default. The [control plane contract](servers-sandcrew-api-foundation.md#organization-settings) owns the ranges.
- `RunnerProfile` (in `ListRunnerProfilesResponse`): `runner_profile_id`, `name`, `guest_os` (SandRun guest OS as the SandCrew enum `GuestOs`), `vcpu_count`, `memory_mib`, `disk_gib`, `allowed`, `selectable` and `ineligibility` (repeated `ProfileIneligibility`).
- `Organization` (in `ListOrganizationsResponse`): `organization_id`, `name`, `caller_role` (`Role`).

### Credential messages

- `SetVendorCredentialRequest`: `organization_id`, `scope` (`CredentialScope`), `vendor` (`AgentVendor`), `kind` (`VendorCredentialKind`) and the `value` (bytes; for `CODEX_AUTH_JSON` the complete file content). The pair of scope and vendor holds at most one credential: a new value replaces the old one and its kind.
- `VendorCredential`: `vendor_credential_id`, `scope`, `vendor`, `kind`, `owner_user_id` (for `USER`), `created_at`, `value_set_at`, `updated_by` (`CREDENTIAL_UPDATE_SOURCE_USER` or `CREDENTIAL_UPDATE_SOURCE_AGENT_REFRESH` as `CredentialUpdateSource`).
- `SetSessionSecretRequest`: `organization_id`, `name` and `value`. `SessionSecret`: `session_secret_id`, `name`, `created_at` and `value_set_at`.

### Session messages

- `Session`: `session_id`, `organization_id`, `owner_user_id`, `label`, `vendor`, `runner_profile_id`, `guest_os`, `state` (`SessionState`), `end_reason` (`SessionEndReason`, set in `ENDED`), `permission_mode` (`PermissionMode`), `created_at`, `started_at`, `paused_at`, `ended_at`, `scheduled_deletion_time` (set while `PAUSED` with a limited retention), `previous_session_id` (for a session from a transcript) and, for the owner only, `agent` (`AgentInfo` from the bridge `hello` and `agent_ready` events: agent version, current mode, available modes and configuration options).
- `GetSession`, `ListSessions` and `WatchSessions` return the owner-only fields only to the owner. Other members get the metadata fields only.
- `CreateSessionRequest`: `organization_id`, `vendor`, `runner_profile_id`, `first_message` (text), optional `label` (at most 100 characters), `session_secret_ids`, optional `mode_id` and optional `config_options` (option ID and value ID pairs). The console offers the model and mode values of `GetAgentOptions`; the bridge applies them after `session/new` and reports a value that the agent rejects as a `bridge_error` with `OPTION_REJECTED`, and the session continues with the agent's default.
- `SendMessageRequest`: `organization_id`, `session_id`, `client_message_id` (UUID v7, for idempotency) and `text`. `AnswerPermissionRequest`: `organization_id`, `session_id`, `permission_request_id` and `option_id`. `CancelTurnRequest`, `SetSessionModeRequest` (`mode_id` or `permission_mode`) and `SetSessionConfigOptionRequest` (`config_option_id`, `value_id`) also carry a `client_message_id`.
- `ListSessionEventsRequest`: `organization_id`, `session_id`, `after_sequence` and `page_size` (maximum 500). The response holds `TranscriptEvent` messages and `next_sequence`.
- `WatchSessionResponse` is a `oneof` of `keepalive`, `event` (`TranscriptEvent`), `session` (the changed `Session`) and `caught_up` (all stored events after the requested sequence were sent).
- `TranscriptEvent`: `sequence`, `time` and `event` (`BridgeEvent` without the `credential_update` case; see below). The server never returns a `credential_update` event.

### Bridge schema

The bridge writes `BridgeEvent` messages, one per line, to the stdout of its exec and to its guest event log. The control plane writes `BridgeInput` messages, one per file, into the guest inbox. The [bridge contract](cmds-sandcrew-bridge-foundation.md) owns the files, the order and the delivery rules.

`BridgeEvent`: `sequence` (`uint64`, starts at 1 and increases by 1 for each event of the session that the guest event log holds), `log_end_offset` (`uint64`, the byte offset in the guest event log after the line of this event), `time` and a `oneof event`:

| Case                  | Message              | Content                                                                                                                                                                                                                                                                                                              |
| --------------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hello`               | `BridgeHello`        | `bridge_version`, `protocol_version` (`major`, `minor`), `vendor`, `agent_version` and `adapter_version` (the pinned versions), `guest_os`, `wrapped_headless`. Always the first event of a bridge process.                                                                                                          |
| `agent_ready`         | `AgentReady`         | `agent_capabilities` (`load_session`, `resume_session`), `agent_session_id` (the ACP session ID), `agent_name` and `agent_reported_version` (from the ACP `agentInfo`, when the agent sends it). Written once after ACP `session/new`, because the agent advertises its capabilities only after it starts.           |
| `input_accepted`      | `InputAccepted`      | `input_id` of the inbox message that the bridge read and applied or queued.                                                                                                                                                                                                                                          |
| `input_rejected`      | `InputRejected`      | `input_id` and `InputRejectionReason`.                                                                                                                                                                                                                                                                               |
| `user_message_chunk`  | `ContentChunk`       | `content` (`ContentBlock`: a `oneof` of `text`, `resource_link` and `unsupported` with the original JSON).                                                                                                                                                                                                           |
| `agent_message_chunk` | `ContentChunk`       | As above.                                                                                                                                                                                                                                                                                                            |
| `agent_thought_chunk` | `ContentChunk`       | As above.                                                                                                                                                                                                                                                                                                            |
| `tool_call`           | `ToolCall`           | `tool_call_id`, `title`, `kind` (`ToolKind`), `status` (`ToolCallStatus`), `content` (repeated `ToolCallContent`: a `oneof` of `block` (`ContentBlock`), `diff` with `path`, `old_text` and `new_text`, and `terminal` with `terminal_id`), `locations` (paths and lines), `raw_input` and `raw_output` (JSON text). |
| `tool_call_update`    | `ToolCallUpdate`     | `tool_call_id` and the changed fields of `ToolCall`, with `raw_output` (JSON text). Scalar fields are `optional`; `content` and `locations` are list wrappers (`ToolCallContentList`, `ToolCallLocationList`) that replace the previous list when set.                                                               |
| `plan`                | `Plan`               | `entries` (repeated `PlanEntry` with `content`, `priority` (`PlanEntryPriority`) and `status` (`PlanEntryStatus`)). Replaces the previous plan.                                                                                                                                                                      |
| `permission_request`  | `PermissionRequest`  | `permission_request_id` (a UUID v7 that the bridge assigns), `tool_call_id`, `options` (repeated `PermissionOption` with `option_id`, `name` and `kind` (`PermissionOptionKind`)) and `tool_call` (the `ToolCallUpdate` that the agent sent with the request).                                                       |
| `permission_response` | `PermissionResponse` | `permission_request_id`, `outcome` (`PermissionOutcome`), `option_id` and `auto_approved` (true when the bridge answered in `AUTO_APPROVE`).                                                                                                                                                                         |
| `turn_ended`          | `TurnEnded`          | `stop_reason` (`StopReason`).                                                                                                                                                                                                                                                                                        |
| `mode_changed`        | `ModeChanged`        | `current_mode_id`, `available_modes` (ID, name, description) and `permission_mode` (`PermissionMode`).                                                                                                                                                                                                               |
| `config_options`      | `ConfigOptions`      | The configuration options of the agent (ID, name, `ConfigOptionCategory`, current value ID and values).                                                                                                                                                                                                              |
| `session_state`       | `AgentSessionState`  | `state` (`AgentActivity`).                                                                                                                                                                                                                                                                                           |
| `bridge_error`        | `BridgeError`        | `kind` (`BridgeErrorKind`) and a message without secrets, prompts or output.                                                                                                                                                                                                                                         |
| `agent_exited`        | `AgentExited`        | `exit_code` or `signal`. The last event of a bridge process when the agent ends.                                                                                                                                                                                                                                     |
| `credential_update`   | `CredentialUpdate`   | `kind` (`VendorCredentialKind`) and `revision`. It carries no credential content. Written only to stdout, never to the guest event log, never stored and never logged. It has no sequence of its own: it repeats the `sequence` and `log_end_offset` of the last logged event.                                       |
| `unknown_update`      | `UnknownUpdate`      | `session_update` (the ACP `sessionUpdate` value) and `raw_json` (the original ACP update).                                                                                                                                                                                                                           |

- Mapping to ACP: the content cases map the ACP `session/update` values `user_message_chunk`, `agent_message_chunk`, `agent_thought_chunk`, `tool_call`, `tool_call_update` and `plan`; `mode_changed` maps `current_mode_update`; `config_options` maps `config_option_update`. ACP updates without a case in this table (for example `available_commands_update`, `usage_update` or a value that a later ACP version adds) become `unknown_update` with the original JSON. A diff is a `ToolCallContent` case, like in ACP.
- Headless-fallback vendors produce the same cases. Their `hello.wrapped_headless` is true.

`BridgeInput`: `input_id` (UUID v7), `create_time` and a `oneof input`:

| Case                | Content                                                                              |
| ------------------- | ------------------------------------------------------------------------------------ |
| `prompt`            | `text`, optional `attachment_path` (a guest path, for the previous transcript file). |
| `permission_answer` | `permission_request_id` and `option_id`.                                             |
| `cancel_turn`       | Empty.                                                                               |
| `set_mode`          | `mode_id` or `permission_mode`.                                                      |
| `set_config_option` | `config_option_id` and `value_id`.                                                   |

The input messages are `PromptInput`, `PermissionAnswerInput`, `CancelTurnInput`, `SetModeInput` (a `oneof target`) and `SetConfigOptionInput`.

`BridgeStartConfig` is the start configuration that the control plane writes as `start.json` (protobuf JSON): `session_id`, `vendor`, `credential_kind` (`VendorCredentialKind` of the session's credential), `permission_mode`, `mode_id` (empty keeps the agent's default) and `config_options` (repeated `ConfigOptionSelection` with `config_option_id` and `value_id`).

### Protocol versions

- `BridgeHello.protocol_version` has a `major` and a `minor` number. The first release is `1.0`.
- A new `minor` adds optional fields, new `oneof` cases or new enum values. A reader that does not know a case or value ignores the event content and keeps its sequence. A new `major` changes the meaning of existing fields, removes a case or changes the transport rules.
- The control plane records the set of supported majors in its code. A bridge whose major is not supported ends its session with `BRIDGE_UNSUPPORTED`.

## Storage

The schemas own no storage. The [control plane contract](servers-sandcrew-api-foundation.md#storage) stores transcript events as protobuf JSON lines of `TranscriptEvent`, and the [bridge contract](cmds-sandcrew-bridge-foundation.md#event-log) stores `BridgeEvent` lines in the guest.

## Security

- No response message carries a credential or a secret value.
- `credential_update` carries no credential content. The control plane reads the changed file itself ([control plane contract](servers-sandcrew-api-foundation.md#credentials-and-secrets)).
- `raw_input`, `raw_output` and `unknown_update.raw_json` are agent data and can contain anything that the agent saw. They are transcript content: only the session owner reads them, and they are never logged.

## Logging

The schemas define no logs. Components log event kinds, sequence numbers and IDs, never event content.

## Build and Test

- `scripts/protos.sh check` (buf lint with the `STANDARD` rules, buf format and the breaking-change check against the base branch) and `scripts/protos.sh generate` from the repository root, according to `protos/AGENTS.md`.
- Schema tests in `protos/delino/sandcrew/v1/schema_test.go`: every enum has its `UNSPECIFIED` zero value, every `BridgeEvent` and `BridgeInput` case round-trips through protobuf JSON, and (with the Connect API) `TranscriptEvent` has no `credential_update` case.
- `pnpm exec turbo run build lint typecheck --filter=@delino/sandcrew-protos` for the TypeScript binding package.

## Dependencies and Integrations

- The same buf, Go protobuf, Connect and `protoc-gen-es` versions as the other schema packages.
- The SandCrew schemas do not import the SandRun or OwnSand schemas. They copy the values they need (for example `GuestOs` and `Role`).
- ACP is the model of the bridge event schema, not a dependency: the schema follows the [ACP schema](https://agentclientprotocol.com/protocol/schema) values listed in the enum table.

## Change Triggers

- Update the [control plane](servers-sandcrew-api-foundation.md), [console](apps-sandcrew-console-foundation.md) and [bridge](cmds-sandcrew-bridge-foundation.md) contracts with every RPC, message, event or enum change they use.
- Decide with each bridge schema change whether it needs a new protocol major version, and update [Protocol versions](#protocol-versions) when the rules change.
- Update the [project index](project-sandcrew.md) when a state, an end reason or the protocol package changes.
